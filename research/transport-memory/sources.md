# Transport dependency evidence

Checked 2026-09-10. curl 8.22.0, OpenSSL 3.6.3 and nghttp2 1.70.0 are **experiment pins**, not an accepted Rui dependency decision. Results apply to the built configuration and negotiated protocol recorded by the harness; system curl is not an equivalent substitute. Source links below target the curl release tag; line references were checked against downloaded raw source.

## Receive buffers and paused streams

[CURLOPT_BUFFERSIZE](https://curl.se/libcurl/c/CURLOPT_BUFFERSIZE.html) documents a single receive transfer buffer per multi handle since 8.7.0, shared by its easy handles. The default request is 16,384 bytes; this option is a size request, not an exact allocation guarantee. It does not bound all transport memory. In [8.22.0 multi.c](https://github.com/curl/curl/blob/curl-8_22_0/lib/multi.c#L3997), `Curl_multi_xfer_buf_borrow` grows the buffer to the current transfer's requested size and returns `CURLE_OUT_OF_MEMORY` on failure. `multi_xfer_bufs_free` (4152) releases it; the no-active-transfer path invokes this at 139–141. Per-easy, protocol, TLS and paused-output buffers remain separate.

[curl_easy_pause](https://curl.se/libcurl/c/curl_easy_pause.html) documents that the complete rejected callback chunk is redelivered after unpause. A callback must not write part of that chunk and then return PAUSE. Unpausing can invoke callbacks synchronously, so scratch ownership and callback state must already be valid. Other active streams require draining a multiplexed socket, which can retain bytes for a paused stream. Automatic decompression can expand retained data beyond compressed wire bytes.

The [8.22.0 HTTP/2 implementation](https://github.com/curl/curl/blob/curl-8_22_0/lib/http2.c#L57) refines the public documentation's approximate 10 MB statement:

- Initial per-stream window: 65,536 bytes (71); desired unthrottled window: 10,485,760 bytes (67, 285–297). A rate limit influences desired credit. A pause sets desired credit to zero (308–309), but cannot recall already granted credit or bytes in flight.
- Advertised connection window: 1,048,576,000 bytes (85, 2474–2475), allowing other streams to progress despite paused peers. This is protocol credit, **not a preallocation**.
- HTTP/2 chunk pool: 16,384-byte chunks, at most 640 spare chunks per connection (59, 79, 177). [bufq.c](https://github.com/curl/curl/blob/curl-8_22_0/lib/bufq.c#L156) allocates chunks on demand; returning a chunk retains it below the spare cap and otherwise frees it (187–197). Pool cleanup releases spares (200–204). Thus up to 10,485,760 payload bytes plus chunk headers can remain as spares for a used connection; actual measurements determine occupancy.
- [cw-out.c](https://github.com/curl/curl/blob/curl-8_22_0/lib/cw-out.c#L348) accumulates paused callback output separately and rejects exceeding `DYN_PAUSE_BUFFER` with `CURLE_TOO_LARGE`. [dynbuf.h](https://github.com/curl/curl/blob/curl-8_22_0/lib/curlx/dynbuf.h#L67) sets that limit to 67,108,864 bytes. This safety ceiling is not a recommended per-stream budget and does not mean ordinary paused HTTP/2 transfers allocate 64 MiB.

Inference for experiment design: pause after some data has flowed as well as at the first callback; keep another stream active, and vary bytes independently from stream count. Early pause or short responses may never exercise expanded credit. Compare equal completed output and concurrency; rate limiting would change workload timing rather than prove equivalent throughput. HTTP/3 needs its own selected backend and measurements; OpenSSL version alone does not establish curl HTTP/3 support.

## Idle connections and attribution

[CURLMOPT_MAXCONNECTS](https://curl.se/libcurl/c/CURLMOPT_MAXCONNECTS.html) bounds retained idle connections. Its default scales to twice attached easy handles; explicit caps evict old idle connections. [8.22.0 conncache.c](https://github.com/curl/curl/blob/curl-8_22_0/lib/conncache.c#L654) confirms this and the default-only 1,000 ms age guard. Setting zero selects the default, **not an empty cache**. [CURLMOPT_MAX_TOTAL_CONNECTIONS](https://curl.se/libcurl/c/CURLMOPT_MAX_TOTAL_CONNECTIONS.html) instead limits simultaneous connections and queues transfers; it is not an equivalent memory improvement if it reduces active work. Completion, easy cleanup and multi cleanup are distinct retained-idle boundaries.

[curl_global_init_mem](https://curl.se/libcurl/c/curl_global_init_mem.html) installs libcurl allocation callbacks; they must be thread-safe when threads or a threaded resolver are involved. In [http2.c 450–469](https://github.com/curl/curl/blob/curl-8_22_0/lib/http2.c#L450), `nghttp2_session_client_new3` receives curl-backed allocators, so the curl bucket includes nghttp2 session allocations. The option object is created separately. Do not describe this bucket as exclusively curl-owned code or claim it captures every dependency allocation.

[OpenSSL 3.6 allocation documentation](https://docs.openssl.org/3.6/man3/OPENSSL_malloc/) permits replacing allocation functions only before allocations occur; `CRYPTO_set_mem_functions` must return 1. Install all three hooks before curl initialization. Requested-live and requested-peak bytes from these hooks exclude allocator metadata, freed-but-retained heap pages, mappings and kernel memory. OpenSSL's old memory-leak APIs are deprecated no-ops; optional allocation-call counts are not live-byte accounting.

Report application scratch bytes, curl-hook bytes (including the nghttp2 session), OpenSSL-hook bytes, process footprint and socket/file counts separately. Socket buffer settings are capacities, not measured resident kernel bytes. Process footprint minus hook totals is not a valid exact kernel/cache attribution. None of these source facts establishes Linux performance, production-runtime qualification or a minimal memory result by itself.

## Follow-up: per-easy send buffers and deferred shutdown

Verified 2026-09-11. [CURLOPT_UPLOAD_BUFFERSIZE](https://curl.se/libcurl/c/CURLOPT_UPLOAD_BUFFERSIZE.html) specifies a 65,536-byte default, 16,384-byte minimum and 2,097,152-byte maximum; it is a preferred size and must not change during an active transfer. [urldata.h 133–135](https://github.com/curl/curl/blob/curl-8_22_0/lib/urldata.h#L133) confirms the pinned constants. The manual's on-demand upload-buffer description does not establish that a download-only easy handle has no send-buffer cost: request headers must also be sent.

In [request.c 76–87](https://github.com/curl/curl/blob/curl-8_22_0/lib/request.c#L76), each easy handle's `SingleRequest` owns a send queue whose chunk size is `upload_buffer_size`. This is separate from the shared multi transfer buffer. `Curl_req_send` and its buffering helper use this queue for outgoing request bytes, including headers (369–377). It uses a soft limit to preserve complete input, so one chunk is not an absolute maximum for large requests. [bufq.c 243–253](https://github.com/curl/curl/blob/curl-8_22_0/lib/bufq.c#L243) shows that reset moves chunks to a spare list rather than freeing them. `Curl_req_free` releases the queue (request.c 174–183), called on easy-handle destruction in [url.c 241](https://github.com/curl/curl/blob/curl-8_22_0/lib/url.c#L241); a changed chunk size also frees/reinitializes it at the next request start. This explains a substantial per-retained-easy multiplier, but the measured approximately 69,336 bytes per handle includes other allocations and is not a source-defined constant. A 16 KiB experiment retains complete request bytes; its timing and exact savings still require measurement.

Cache eviction also has a separate release boundary. [conncache.c 220–228](https://github.com/curl/curl/blob/curl-8_22_0/lib/conncache.c#L220) attempts shutdown once and places unfinished connections on `cshutdn` instead of immediately terminating them. The multi administration path services that list through `Curl_cshutdn_perform` in [multi.c 2753–2763](https://github.com/curl/curl/blob/curl-8_22_0/lib/multi.c#L2753). Thus an evicted TLS connection can retain allocations/socket state while graceful shutdown is pending. Continue driving the multi event loop to observe settled idle retention; an immediate post-completion sample alone cannot establish whether a cache cap released its memory. Distinguish the cache, pending shutdown and final multi cleanup in reporting.
