# Compaction policy and ownership sources

Inspected October 14, 2026. These pinned client sources explain policy ownership and replay choices. They do not prove subscription-server support, account entitlement, or live encrypted-state compatibility. Rui's accepted behavior is in [Architecture](../ARCHITECTURE.md#choosing-and-validating-compacted-context).

## Pi 1.0

At earendil-works/pi [v1.0.0](https://github.com/earendil-works/pi/tree/a13d35a742c6ef8462812a28fbe1d8c8b7431c32), compaction defaults to enabled, with `reserveTokens: 16384` and `keepRecentTokens: 20000` ([declarations](https://github.com/earendil-works/pi/blob/a13d35a742c6ef8462812a28fbe1d8c8b7431c32/packages/coding-agent/src/core/settings-manager.ts#L18-L33)). Exact `provider/modelId` overrides resolve each token field independently through the ordinary settings to the built-in default ([resolution](https://github.com/earendil-works/pi/blob/a13d35a742c6ef8462812a28fbe1d8c8b7431c32/packages/coding-agent/src/core/settings-manager.ts#L914-L974)). `enabled` is separate from those overrides. Omission permits fallback; JSON `null` is invalid ([tests](https://github.com/earendil-works/pi/blob/a13d35a742c6ef8462812a28fbe1d8c8b7431c32/packages/coding-agent/test/settings-manager-compaction.test.ts#L115-L160)).

Pi compares context tokens strictly above `contextWindow - reserveTokens` ([trigger](https://github.com/earendil-works/pi/blob/a13d35a742c6ef8462812a28fbe1d8c8b7431c32/packages/coding-agent/src/core/compaction/compaction.ts#L264-L270)). The model supplies its limits; agent settings supply compaction policy. Pi stores an application-generated summary in a CompactionEntry while retaining original entries ([storage and reconstruction](https://github.com/earendil-works/pi/blob/a13d35a742c6ef8462812a28fbe1d8c8b7431c32/packages/coding-agent/docs/compaction.md#L43-L98)). Summary output is capped separately, at the smaller of 80% of reserve and a positive model `maxTokens` ([calculation](https://github.com/earendil-works/pi/blob/a13d35a742c6ef8462812a28fbe1d8c8b7431c32/packages/coding-agent/src/core/compaction/compaction.ts#L695-L715)).

## OpenCode

At anomalyco/opencode [34d8ded](https://github.com/anomalyco/opencode/tree/34d8ded0c58dd66808c1d60e081e8c66da12a896), public policy exposes `compaction.auto`, `compaction.buffer`, and `compaction.keep.tokens` ([schema](https://github.com/anomalyco/opencode/blob/34d8ded0c58dd66808c1d60e081e8c66da12a896/packages/schema/src/config/compaction.ts#L6-L14)). The owning service defaults to automatic compaction and 15,000 retained tokens. Disabling auto also disables overflow recovery, but not manual compaction ([service](https://github.com/anomalyco/opencode/blob/34d8ded0c58dd66808c1d60e081e8c66da12a896/packages/core/src/session/compaction.ts#L195-L233)).

The window is `limit.input || limit.context`. An unknown window does not trigger automatic compaction. The default buffer is 10% of the window, with a 16,000-token minimum for windows of at least 32,000 tokens ([calculation](https://github.com/anomalyco/opencode/blob/34d8ded0c58dd66808c1d60e081e8c66da12a896/packages/core/src/session/compaction.ts#L900-L912)). Model metadata and compaction configuration remain separate.

Summary mode stores a summary and recent conversation as text; native mode stores provider replacement material. The trigger route retains recent real user messages locally. Native provenance must match the endpoint, and request-hook rerouting rejects ([implementation](https://github.com/anomalyco/opencode/blob/34d8ded0c58dd66808c1d60e081e8c66da12a896/packages/core/src/session/compaction.ts#L253-L371)). Model settings override provider settings for native versus summary mode; incompatible encrypted checkpoints fall back to original conversation on model switch ([documentation](https://github.com/anomalyco/opencode/blob/34d8ded0c58dd66808c1d60e081e8c66da12a896/services/www/src/docs/content/compaction.mdx#L89-L127)). Rui deliberately does not adopt that fallback or OpenCode's legacy configuration aliases.

## Codex

At openai/codex [21c1616](https://github.com/openai/codex/tree/21c16161191ff965031d1ac41fe9046011610743), the exact `gpt-6-luna` catalog entry has a 272,000-token context window and a null explicit auto-compaction limit ([metadata](https://github.com/openai/codex/blob/21c16161191ff965031d1ac41fe9046011610743/codex-rs/models-manager/models.json#L523-L560)). The client derives its unoverridden automatic limit as 90% of the window, or 244,800 tokens ([method](https://github.com/openai/codex/blob/21c16161191ff965031d1ac41fe9046011610743/codex-rs/protocol/src/openai_models.rs#L517-L540)). Usable inference context is a separate calculation. Subtracting another guessed output allowance from 244,800 would count headroom twice. User configuration can override context and auto-compaction metadata ([override](https://github.com/openai/codex/blob/21c16161191ff965031d1ac41fe9046011610743/codex-rs/models-manager/src/model_info.rs#L19-L31)). These are exact-model client facts, not defaults inferred for aliases or unknown models.

The V2 route appends a request-only `compaction_trigger` to history and uses ordinary Responses streaming ([construction](https://github.com/openai/codex/blob/21c16161191ff965031d1ac41fe9046011610743/codex-rs/core/src/compact_remote_v2_attempt.rs#L167-L196), [send](https://github.com/openai/codex/blob/21c16161191ff965031d1ac41fe9046011610743/codex-rs/core/src/compact_remote_v2.rs#L286-L353)). Collection requires completion and exactly one provider compaction item ([collection](https://github.com/openai/codex/blob/21c16161191ff965031d1ac41fe9046011610743/codex-rs/core/src/compact_remote_v2.rs#L418-L504)). Codex installs that item alongside selected retained input using its own history-replacement mechanism ([installation](https://github.com/openai/codex/blob/21c16161191ff965031d1ac41fe9046011610743/codex-rs/core/src/compact_remote_v2_installation.rs#L176-L228)). This does not establish that every Codex route uses this mechanism or that the server rejects a standalone compact endpoint.

## Application to Rui

The useful shared distinction is model/provider capability versus user policy. Rui keeps defaults in its Codex capability, nullable overrides on Session revisions, and resolved values on each admitted Operation. Explicit null resets an override; it is Rui's protocol choice, not Pi's JSON behavior.

Rui retains immutable Conversation and complete Operation-owned provider output. It derives a base from the producing Operation and anchor ordinal instead of adding a summary/checkpoint entity. It adopts neither local summary generation nor automatic model fallback. Synthetic native fixtures qualify these ownership and request-shape choices; live compaction followed by encrypted-state continuation remains a separate opt-in check.
