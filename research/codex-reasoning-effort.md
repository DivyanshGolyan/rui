## Pinned first-party source

At OpenAI Codex [`968835997714baaff199cfed5f89a2c65d8ca77d`](https://github.com/openai/codex/tree/968835997714baaff199cfed5f89a2c65d8ca77d):

- The ordinary client builds a top-level `reasoning` object with an optional string `effort`, alongside `store:false`, `stream:true` and `include:["reasoning.encrypted_content"]` ([builder](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/client.rs#L763-L781), [request](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/client.rs#L845-L889)). Thus a selected ordinary effort is `"reasoning":{"effort":"high"}` (possibly with other reasoning fields), **not** a top-level `reasoning_effort` or a replay-item field. The optional `effort` field is omitted when absent; Codex's ordinary path sets `reasoning: Some(...)`, while the outer request type would serialize `reasoning: None` as JSON `null`, not omit it ([Serde fields](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/codex-api/src/common.rs#L156-L164), [outer field](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/codex-api/src/common.rs#L259-L275)). This is a client serialization fact, not a backend equivalence claim.
- Codex's **generic client** enum spells `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, `ultra`, `persistent` and future custom strings ([enum and serializer](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/protocol/src/openai_models.rs#L55-L87), [parser](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/protocol/src/openai_models.rs#L139-L155)). `ultra` resolves via model-specific fallbacks, `persistent` resolves to wire string `disabled`, and ordinary values otherwise pass through without general supported-level validation ([resolver](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/protocol/src/openai_models/reasoning_effort.rs#L8-L40)). These are **not** the supported values for `gpt-6-luna`. The pinned generic Python Responses schema lists nullable `none`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, warns that not all models support each value, and makes both `reasoning` and `effort` optional ([effort type](https://github.com/openai/openai-python/blob/adb212e116323fcec4b4811d20ba9eb78280c24c/src/openai/types/shared_params/reasoning_effort.py#L1-L10), [qualification caveat](https://github.com/openai/openai-python/blob/adb212e116323fcec4b4811d20ba9eb78280c24c/src/openai/types/shared_params/reasoning.py#L29-L37), [request type](https://github.com/openai/openai-python/blob/adb212e116323fcec4b4811d20ba9eb78280c24c/src/openai/types/responses/response_create_params.py#L199-L203)). Neither SDK schema nor client enum certifies this subscription model.
- Unset **Codex user configuration** falls back to `model_info.default_reasoning_level`, then the client emits that resolved value when the catalog supplies one ([step selection](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/session/step_settings.rs#L79-L91), [request builder](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/client.rs#L763-L781)). This is **Codex's client-side default**, not the server's behavior on a missing `reasoning` field. `none` is a real effort value, not “provider default”; `null`, `{}`, an absent `effort` key and an absent `reasoning` object are different representations with no established identical backend meaning. Resetting Rui's setting to provider default therefore means clearing its persistent explicit choice and returning to the same absent top-level `reasoning` shape as a new Rui Session, not sending `none`, `null` or an invented `default` value. The server's actual default/effective effort remains unobserved.
- The pinned bundled catalog has **no `gpt-6-luna` entry**. Its distinct [`gpt-5.6-luna` entry](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/models-manager/models.json#L428-L484) advertises `medium` default and `low`, `medium`, `high`, `xhigh`, `max`. Do not transfer those values/default to `gpt-6-luna`. Codex [loads bundled models](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/models-manager/src/manager.rs#L298-L316) but [can fetch an authenticated remote catalog](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/models-manager/src/manager.rs#L434-L499); bundled absence is not proof of server absence. The exact model's successful Rui calls below establish availability for that account/run, not an effort matrix.
- Each ordinary sampling request selects effort again ([sampling call](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/session/turn.rs#L2421-L2435)); the remote-v2 compaction request appends a `compaction_trigger` to reconstructed input and invokes the same client with a compaction effort selection ([trigger](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/compact_remote_v2_attempt.rs#L70-L110), [request](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/compact_remote_v2.rs#L372-L404)). Codex's optional context-window pin shares an effort between sampling and compaction; it is client policy, including non-mutating fallback-model lookup, **not** evidence that Rui must implement that pin ([selection](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/session/reasoning_effort.rs#L92-L127)). Compaction retains selected host input and its returned opaque item for later reconstruction ([collector](https://github.com/openai/codex/blob/968835997714baaff199cfed5f89a2c65d8ca77d/codex-rs/core/src/compact_remote_v2.rs#L427-L517)). Effort belongs to **each request envelope**, not a saved encrypted reasoning or compaction item's public setting. A new effort on a later tool continuation or post-compaction request must still replay the prior private items; source shape alone does not prove the backend accepts their combination. Stateless replacement Attempts should reproduce their originating Operation's frozen envelope, not select current Session settings.

## Rui evidence and remaining proof

The merged [request encoder](../src/model_adapter.zig) emits `model`, `store:false`, `stream:true`, `include`, `instructions` and `input` without any `reasoning` field; its [minimal golden](../src/model_adapter.zig) checks exact bytes. The synthetic [managed continuation fixture](../tests/integration/codex_integration.py) checks private reasoning and the approved Tool Result in the next request, not effort selection or compaction. These are deterministic request/ownership facts, not model-specific effort support.

The [native live journey and recorded limits](../VERIFICATION.md#context-provider-output-and-compaction) at exact Rui revision `3d4c0e0f2cc3d5bfca3fa524cba735fe39fbda41` exercised `gpt-6-luna` on Linux x86-64 and macOS arm64: four response bodies reported that model, initial private reasoning was captured, tool continuation and fresh-Host replay succeeded. It sent the above **omitted** `reasoning` shape, not an explicit effort. Reasoning-token counts (380/379 first response, zero on Bash proposal/continuation) do not reveal a provider default or test other values. Served-model headers and provider correlation were unavailable. This is live same-binding continuation evidence, not proof of `gpt-6-luna`'s effort matrix, explicit reset behavior, effort changes across replay, compaction compatibility or a backend effective default.

To qualify a closed explicit value set for this exact binding, obtain authorized, payload-free live requests with a known account/route and exact model string, record accepted/rejected HTTP outcomes plus response model/usage and available served identifiers for **each** candidate; exercise a valid private-reasoning → tool-result continuation after an effort change and compaction → continuation at the selected levels. Compare an omitted request and reset-to-omission against explicit values without inferring their internal effort merely from latency or token count. Preserve rejection as an Operation failure, not a fallback retry with private state discarded. A remote model-catalog snapshot tied to account/time may guide candidates but is still not proof of backend acceptance. #319 owns the closed public choices, CLI reset spelling and proof boundary after the human design exchange; this research does not choose them or expand the qualified binding.
