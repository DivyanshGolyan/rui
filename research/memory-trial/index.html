What occupies the Host’s memory?

One local model request, a 100,000-byte answer, eight allocated execution slots. These are measurements of this workload—not a verdict about what is justified.

The largest category: thread-local signal-stack storage

Two live blocks are reported as 288 KiB each. Their allocation histories lead to Zig’s Thread.maybeAttachSignalStack. The installed standard library declares a 256 KiB alternate signal stack per participating thread, used for signal handling. macOS allocates a thread-local block containing that storage.

Zig field256 KiB signal stack
Requested block262,160 bytes in each observed history entry
Allocated size class294,912 bytes each
Two live blocks = 576 KiB

This is a concrete example of a field, its multiplier and allocator rounding. It is not the normal thread stack. No proposal to remove it is implied.

SQLite, OpenSSL, curl and the unassigned remainder

SQLite’s heap category totals 407,264 bytes and agrees with its current allocator diagnostic at this snapshot. Its 261,760-byte pager cache is included, not additional. OpenSSL categories total 144,256 bytes even though this fixture uses HTTP; initialization runs when transport is enabled. This does not measure a TLS handshake.

The Zig allocator category includes the 9,728-byte slot array, but other allocations need further ownership attribution. “Other / unattributed” includes OS runtime objects and 37,728 bytes explicitly lacking stack backtraces. We preserve that uncertainty.

3. Allocated slots cost memory even when idle

The compiled ExecutionSlot occupies 1,216 bytes. Its states share union storage: free, provider, cleanup or retained cleanup metadata. Changing state does not shrink the slot.

5. What we can explain—and what still needs work

Established

Live heap breakdown, large allocation origins, exact slot layout, completed request and cleanup, physical versus virtual distinction.

Still incomplete

Each stack’s thread owner, remaining object ownership, transient peaks by operation, repeated-work and concurrency behavior, TLS costs.

Production changes

None. Instruments required a disposable binary copy signed for debugger attachment. Original source and binary were preserved.

The useful artifact is this explanation plus the native evidence. A profiler shows where allocations originate; field layout and owning code explain what they contain and how long they belong to the Host.

Evidence and scope

Measured commit d559412, Zig 0.16 ReleaseSafe, macOS ARM64. Local HTTP fixture; no live provider, tools or Workflow evaluator. Instruments attached after startup. Measurements include diagnostic effects and do not qualify production limits.
