## OnePage inferences to evaluate

An on-disk spillover index with bounded reads is consistent with these separation principles, but is our design inference. It can avoid memory growth with retained history; it cannot by itself bound open descriptors, physical files, directory metadata or deletion work. A positive charged record for each file can derive a logical population bound; it still does not account for filesystem allocation or establish acceptable cleanup latency.

For a command whose output is retained, ownership still has to cover writing, reader protection, eligibility and physical deletion. Deletion failure or a still-open OnePage reader cannot be treated as reclaimed storage merely because an index entry disappeared. Restart behavior must distinguish disposable scratch from accepted results. These are local filesystem and OnePage contract questions not answered by the posts.

No source here justifies replacing the accepted scheduler, adding distributed leases, replaying uncertain tools, or changing retained output into a refillable cache. The useful borrowing is narrower: keep durable facts on storage, hold only current work in memory, give mutations one owner, and earn additional mechanisms with a concrete failure or cost.
