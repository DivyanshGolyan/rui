# Markdown parser candidates for bounded terminal output

Primary-source inspection, 2026-09-27: [MD4C `7fc1815`](https://github.com/mity/md4c/tree/7fc1815a5eeba2af7d6120a76202bf59f3b6e6e4), [cmark-gfm `499789b`](https://github.com/github/cmark-gfm/tree/499789b49373bfa045d0e7547e5ee63444c77bca), and [mdflow `1efe344`](https://github.com/cjccjj/mdflow/tree/1efe344a7ee2344deef5db6c5e28ae33926fb235). This is dependency research, not a Rui contract change or runtime qualification. **The target is local `ux/15-16` at `470f621`:** a completed saved answer is read in 4-KiB chunks; `feed/finish` emits safely escaped terminal output with at most 128-byte prefix, 256-byte inline candidate and 4-KiB pending fence, and resident memory independent of answer length. Rui owns control escaping and style mapping.

**Conclusion:** None of these unmodified parsers supplies both standard Markdown interpretation and that resident-memory guarantee. SAX output does not imply streamed input (MD4C); chunked input does not imply streamed output or bounded state (cmark-gfm); even real forward callbacks do not bound unfinished constructs (mdflow). A mature drop-in replacement is not established. Keep the local bounded semantics unless a proposed change explicitly budgets every parser-held population, states its Markdown deviations, and verifies worst cases.

**Completed input changes the design space, not these APIs.** CommonMark [allows definitions after their uses](https://spec.commonmark.org/0.31.2/#link-reference-definitions) and [describes block/definition collection before inline interpretation](https://spec.commonmark.org/0.31.2/#appendix-a-parsing-strategy). For example, `[x]` may be text until a later `[x]: /url` makes it a link. A second read over the already-saved answer could discover later syntax before any terminal output, avoiding live-stream latency/repainting. But calling either library twice still requires MD4C's full contiguous source and growing records, or cmark-gfm's complete tree, **on each pass**. A new file-backed index/re-read algorithm might move state off-RAM at additional I/O and complexity; neither inspected API offers it. Smaller independent chunks change Markdown boundaries/forward references. Preserve exact text and safe escaping even if styles deliberately support only the bounded subset; do not describe that subset as full CommonMark/GFM.

**Bounded syntax counterexample:** The [CommonMark 0.31.2 examples](https://spec.commonmark.org/0.31.2/#example-439) are HTML conformance cases, not terminal-output goldens. Select cases by Rui's supported subset and translate their visible text/style independently; do not require all 652 to pass. Example 439, `foo *****`, must remain literal in both; example 467, `***foo***`, is bold+italic in CommonMark but deliberately literal under Rui's unsupported-nesting fallback. Rui's one-byte-at-a-time [renderer regression](../src/AnswerRenderer.zig) also checks `***x*** then **ok**`: the triple run stays literal and the later pair is bold. Before the fix, `zig build test-logic -Dtest-filter='unsupported asterisk runs'` failed at the first literal-star assertion, producing `foo ` followed by bold `*` instead of `foo *****`. Adding example 440, `foo **\***`, exposed an independent closing-delimiter error: the escaped star left the bold span. Rui retains the literal backslash by contract (unlike CommonMark) but now styles the escaped star with it. The targeted test then passed; the existing 16-MiB discard-writer test checks Rui's fixed parser size and forward output, not a dependency's heap use. The candidate API/lifetime failures above rule out direct replacement before running a vendor output-compatibility suite; no candidate binary or memory benchmark was qualified here.
