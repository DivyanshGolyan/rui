[Call classification and Bash denial](../integration/dispatch_integration.py): the development trace feeds valid Bash, unknown-tool and malformed-argument calls through loopback HTTP and the production provider interpreter. Core classifies them against the frozen catalog in one Store transaction, preserves valid siblings as exact Actions, and saves stable call-local rejections without Action, permission, Attempt or custody. The trace pages pending requests without denying an earlier sibling, reads exact escaped identities/arguments, loses a keyed denial reply, restarts, replays its answer, and recovers the denied Action's original identity, descriptor and outcome alongside rejection facts and its unresolved sibling. It separately proves stale denial after a completed stop. For the actual denial/stop race, a test-only owner phase gate holds the first control after observed Store-mutex acquisition until the competing control is observed queued; both commit orders assert exact denied/cancelled sibling outcomes, cancelled Turn terminality, zero custody and no Bash launch. Store tests cover mixed-call order, schema-invalid arguments, deterministic unavailable-tool rejection, frozen-catalog changes, SQL invariants, rollback, ask→bypass provenance and reopen of the exact denied row and call content. The cardinality test validates 1,000 trustworthy envelopes from one sealed response with fixed-size resident output and exactly 520,000 charged metadata bytes: five 104-byte disk records per call, including the already-required private output item. Canonical descriptor lengths remain consumer-bounded and stream through 4 KiB windows. No fixture launches Bash. This is deterministic development evidence only: Bash execution and Action Attempts are unavailable in this slice, Tool Result publication belongs to the next slice, and this does not qualify allow-once, process execution, model continuation, a live provider, macOS runtime, Linux filesystem durability, power loss or end-to-end proposal-load memory/latency.
