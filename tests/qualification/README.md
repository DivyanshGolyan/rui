[Call classification and Bash denial](../integration/dispatch_integration.py): the development trace feeds valid Bash, unknown-tool and malformed-argument calls through loopback HTTP and the production provider interpreter. Core classifies them against the frozen catalog in one Store transaction, preserves valid siblings as exact Actions, and saves stable call-local rejections without Action, permission, Attempt or custody. The trace pages pending requests without denying an earlier sibling, reads exact escaped identities/arguments, loses a keyed denial reply, restarts, replays its answer, recovers rejection facts and races a second denial with Session stop. Store tests cover mixed-call order, schema-invalid arguments, deterministic unavailable-tool rejection, frozen-catalog changes, SQL invariants, rollback, ask→bypass provenance and reopen. The cardinality test validates 1,000 trustworthy envelopes from one sealed response with fixed-size resident output and exactly 520,000 charged metadata bytes: five 104-byte disk records per call, including the already-required private output item. Canonical descriptor lengths remain consumer-bounded and stream through 4 KiB windows. No fixture launches Bash. This is deterministic development evidence only: Tool Result publication belongs to the next slice, and this does not qualify allow-once, process execution, model continuation, a live provider, macOS runtime, Linux filesystem durability, power loss or end-to-end proposal-load memory/latency.

[Model output](model-output/main.go): `zig build measure-model-output`; [historical full results](model-output/results.json). Measures the production issue-173 Host in three independent families. Growth cases use a 100,000-byte ordinary answer and reasoning-item counts of 1/4/32 in fresh Stores at Active Capacity 1. Capacity cases run two same-Host 60-second rounds at capacities 1/8/16 with 30 realistic 260-byte SSE events/second per stream and capacity 100 with 100 events/second per stream, recording rational pacing and verifying work counts, capture, result identity, scratch/custody release, memory and Host CPU while the same Host remains live. After both rounds and confirmed Host stop/reap, private SQLite audits verify every round-specific durable row before final qualification. Spill-on and spill-off cases both import a 100 KB answer through a 32 KiB test-only SQLite cache, verify its signed raw setting separately from actual cache-used bytes, and require respectively positive and zero spill-counter movement without changing the 4 MiB production default. The full run passed growth, spill and capacities 8/16, but remained incomplete at capacities 1/100 because the fixture's unchanged lateness/gap oracle rejected some streams despite exact work and resource observations within target. After adding two-back catch-up spacing without relaxing that oracle, exact-revision [capacity-1](model-output/2026-09-15-capacity-1-rerun.json) and [capacity-100](model-output/2026-09-15-capacity-100-rerun.json) reruns eliminated burst violations but retained the timing-incomplete result. Mac-only loopback HTTP evidence; it does not qualify TLS trust, a live provider, Linux runtime behavior, retry of interrupted Attempts, power loss or the default-capacity 1,000-operation finished-product workload. The `-projection` runner option adds 1/4/8 KiB representative cases and a 100 KB stress case, each plain and escape-heavy: `GOTOOLCHAIN=local go -C tests/qualification run -mod=readonly ./model-output -projection -output /tmp/projections.json /absolute/path/to/rui`. [Projection results](model-output/2026-09-15-projections.json) record the 4 KiB source window, metadata-only public answers, completion and delivery-with-verification timings, and bounded measured process memory; aggregate concurrent-reader qualification remains separate.

Mac-only loopback HTTP evidence; it does not qualify TLS trust, live-provider behavior, Linux runtime behavior or power loss.

[Model control](model-control/main.go): `zig build measure-model-control`; [historical results](model-control/results.json). The historical run measured the production issue-175 Host at idle, with 10 stalled incomplete ingresses across two fill/drain rounds, with eight live model streams cancelled by one exact interruption plus seven Session stops, and with 10 fully captured reports held during both control-first settlement loss and real Store import of one streamed 100,000-byte answer while two later controls queue. It then starts 10 complete result deliveries, uses a 4 KiB test-only socket send buffer and a status-prefix-only reader to prove those handlers remain blocked, acknowledges a protected control, and independently verifies a clean reread. Records protected-control acknowledgment latency, transport disconnects, descriptors, physical footprint, retained resource deltas and output integrity. Both ingress drains released all 10 connection descriptor/socket rows; see the recorded results for run-specific OS counters. Two rounds do not qualify long-duration churn. Mac-only loopback HTTP evidence; it does not qualify TLS trust, live-provider behavior, Linux runtime behavior, tools, Workflow cancellation or power loss.
