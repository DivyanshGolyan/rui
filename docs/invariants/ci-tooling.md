# Invariants: CI tooling and policy checks

[Test requirements](../verification/testing.md) own the rules and the row format. Every test in this area owns one row; a bug that no row covers changes this catalog.

## Invariants

CI policy is a caller-facing interface to contributors and release operators; checks of its documented decisions have owners here. Checks that merely freeze workflow layout, implementation names, or test harness plumbing have no independent invariant. Product behavior itself belongs to its product area's catalog.

## Seams the harness must provide

- Extract pure admission and promotion decisions from workflow expressions in `.github/workflows/check.yml` and `.github/workflows/promote.yml`, with a single workflow consumer; fake job results and immutable SHAs.
- Inject Git/release service, artifact download, executor and clock at the public policy boundaries in `tests/ci/release.py`, `release_publication.py`, `build_artifact.py`, `run_selected.py`, `quarantine.py` and `recheck_wire_prs.py`; use private temporary Git repositories and files, no hosted service.
- Factor cache publication and stack-budget decisions into public pure policy APIs in `.github/actions/setup/caches/save-keys.cjs` and `tests/ci/stack_frames.py`; feed independent manifest and call-graph values.
- Extract runner install and removal orchestration behind fake account and runner-service adapters in `tests/ci/mac-runner/install.sh` and its helpers; inject workflow run records for `.github/workflows/infra-retry.yml`.
- Installer needs injected local archive transport and isolated destination (`release/install.sh`); no real network or machine PATH edits.
