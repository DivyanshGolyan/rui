# Use one Host Store with per-Session ledgers

OnePage stores every ordered Session Ledger and host-wide durable coordination record in one SQLite Host Store accessed only through a singleton Storage Owner. Applications compose exactly one SQLite-owning `HostRuntime` per process; Harness receives that runtime rather than a connection owner, directory handle, and Activation pool separately. Host Runtime owns SQLite's process-global heap allowance. Storage Owner serializes complete requests on one connection. One semantic commit accepts one typed transaction, derives its canonical payload and normalized writes, and publishes one Session sequence and ledger row. SQLite assigns Completion Inbox identity; Conversation rows are committed-only. Normalized tables exist only for independently queried Completion and Conversation data. SQLite owns physical transactions, journaling, locking, and page layout, while OnePage retains semantic validation, effect uncertainty, durable-before-reference blobs, bounded recovery, and per-Session authority. The host-wide store amortizes resident database machinery at the accepted cost of a shared corruption, capacity, maintenance, and head-of-line-blocking failure domain.
