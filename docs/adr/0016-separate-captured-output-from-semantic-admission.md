# Separate captured model output from semantic admission

OnePage streams each bounded provider outcome into immutable Captured Model Output and publishes Completion evidence before assigning provider-neutral meaning to those bytes. The existing Harness owner path later validates that exact capture once and atomically commits either its typed Result meaning or a typed terminal failure with Core State through the Session Ledger. Conversation construction, provider-request reconstruction, ordinary recovery, and built-in execution consume that admitted authority and do not repeatedly parse and reserialize matching immutable JSON.

Provider dispatch is synchronous. The provider receives only an append-only candidate capability and returns one typed candidate-or-failure outcome. The Host owns the draft, the only transition to a sealed response, and failure replacement. A draft is unpublished scratch and never resume authority. Drafts occupy a wholly owned flat scratch namespace. Once a new ownership epoch holds the Session lock, startup validates and removes at most 16 exact draft files, which is sixteen times V1's single live writer capacity; an extra or unexpected entry fails recovery before any deletion. Sealed history is outside draft cleanup, and partials are never opened as response evidence. No database transaction spans the network call.

Completion Inbox publication is the recovery discovery point. A sealed response becomes recoverable Attempt evidence only when one committed Completion row binds its exact reference and digest. If the process dies after seal but before that publication, the sealed blob is a non-authoritative orphan: recovery does not search for or infer a Completion from it. Recovery records that the prior model dispatch may duplicate work or billing, then admits a replacement Attempt with a new response reference. If Completion publication committed, a fresh owner validates and admits those exact captured bytes without provider redispatch. This policy needs no sealed-blob discovery index, provider sidecar, or second protocol.

Provider wire parsing may retain bounded adapter-private decoded values until the complete enclosing event identifies which value is semantically relevant. That scratch grows only with actual decoded content, is capped before allocation, cannot be published, and is released after terminal settlement. The maximum legal wire event is a counted work and compatibility bound rather than a same-sized resident buffer. Once the event and terminal state validate, the adapter emits through the existing house encoder and append-only candidate capability; this decision adds no provider-visible mutable transaction or second canonical format.

V1 binds exact strict JSON tool-argument bytes, their identity, the Validation Profile, and the Operation's Tool Catalog rather than requiring semantic-equivalent JSON values to share canonical bytes. Built-in Bash and patch calls additionally derive durable typed effect descriptors before external dispatch. The large bounded parser workspace is reconstructible CPU scratch shared by semantic-validation capacity, initially one, and is never assigned to every Active Credit or retained during provider or subprocess waits. This preserves bounded failure behavior without turning an Active Credit into a physical memory bundle or adding a second semantic authority.
