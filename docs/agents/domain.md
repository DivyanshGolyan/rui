# Domain Authority

Rui keeps its domain model in the accepted contract. `ARCHITECTURE.md` owns accepted terminology, behavior, decisions and rationale; applicable `VERIFICATION.md` sections own the required evidence. GitHub issues hold unresolved decisions and research.

## Before exploring

- Read `ARCHITECTURE.md` sections owning the affected behavior and terminology.
- Read applicable `VERIFICATION.md` cases.
- For issue-driven work, read the live issue and relevant discussion.

Do not create `CONTEXT.md` or ADRs. When terminology or a decision becomes accepted, edit its owning contract section and affected verification cases. Leave unresolved choices in the issue tracker.

## Vocabulary and authority

Use terms as defined in `ARCHITECTURE.md`. Do not introduce synonyms for established domain concepts. Each requirement keeps one owning home under the repository rules in `AGENTS.md`.

If a proposed decision contradicts the accepted contract, identify the conflict explicitly rather than silently overriding it.
