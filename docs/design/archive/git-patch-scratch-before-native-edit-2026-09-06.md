# Superseded Git Patch scratch contract

Historical accepted design before the native Edit decision. Not current implementation instructions. Superseded by [ADR-0027](../../adr/0027-use-an-in-process-exact-edit-module.md).

## Patch helper scratch ownership

Patch's named private snapshot is the narrow exception to immediately unlinked scratch: Git requires a pathname. It remains disposable, non-authoritative and charged to the same aggregate scratch allowance. Each active Patch owns at most one private tree containing its one regular target and the directories required by the bounded target path. No tree is retained per historical Operation or failed try. Patch input and other capture files remain separately charged while they coexist.

Before creating that snapshot, reserve **S + P** logical bytes with checked arithmetic, where S is the sealed source length and P is the admitted text-patch length. This covers the maximum replacement for the supported one-file, literal-text modification: added bytes come from the patch. The reservation covers the snapshot and its replacement, not two independently charged allowances. Keep it until the helper has exited, all relevant handles/I/O have finished, and the tree has been removed. Close the snapshot preimage handle immediately after hashing and saving its required metadata, before Git runs, so the removed old inode does not coexist unnecessarily with its replacement. The live Workspace target retains its separate effect ownership and reconciliation rules.

Use a closed Git invocation and explicit environment for private application: no inherited Git variables, system/global Git configuration or system/global attributes; `core.attributesFile=/dev/null`, `core.autocrlf=false`, and `apply --no-index --whitespace=nowarn -`. Set repository discovery's ceiling to the controlled scratch parent, keep the application tree outside a repository and create no `.git` there. The existing preflight admits exactly one regular text modification and excludes binary/multiple-file/create/delete/rename/copy/mode-change paths. Do not enable reject files, indexes, three-way application or working-tree transformations. Preserve exact byte output even when the target is `.gitattributes`. Supported-build qualification must verify this behavior; an unsupported invocation/build fails explicitly, not by silently changing content.

Before exec, apply child-only `RLIMIT_FSIZE = S + P` and disable core dumps. This is a per-file enforcement guard; the closed invocation and one-target tree supply the file-count proof. Git errors, limits and partial scratch cannot publish successful or partial Patch results. Do not monitor directory sizes during writes or treat after-the-fact size checks as reservation. No external helper may write into the live Workspace through this path; the existing Patch owner applies the verified expected postimage under its ordinary effect/recovery rules.

One stable OS-held scratch-area lock protects the named scratch lifetime. Acquire it before startup cleanup or admitting new scratch owners. Explicitly inherit that same locked open file description into every helper that can still touch the area; inherit neither semantic Store access nor unrelated descriptors. Keep the lock file inode stable and close references rather than explicitly unlocking the shared description while a helper survives. After Host death, a surviving helper prevents a new Host from cleaning or reusing its area. Failure to acquire rejects startup without waiting indefinitely or deleting live files. Once exclusive ownership is acquired, stream removal of owned stale trees before new admission, including after a smaller-cap restart. Failed cleanup prevents a fresh population; no durable per-file ledger or background garbage collector is introduced.

During a live Host, failed tree removal retains its reservation and Physical Custody record; it cannot return capacity while leaving named files behind. Report the failure without a busy cleanup loop or an unbounded detached backlog. Successful ordinary cleanup releases ownership; explicit shutdown/restart retains the existing effect-aware behavior. A cleanup failure after committed effect success cannot rewrite the successful Resolution. This mechanism adds one reservation value per active Patch and one scratch lock, not a resident copy of reserved bytes, per-Patch lock or permanent worker. Git's own heap/process footprint remains included in OnePage's resource qualification.
