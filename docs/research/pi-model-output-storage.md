# Pi model-output storage

## Source checked

Fresh depth-1 clone of [`badlogic/pi-mono`](https://github.com/badlogic/pi-mono) at commit [`7d399e7be83cb7ffb0236b2925ba21f2bc9efe18`](https://github.com/badlogic/pi-mono/commit/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18) (2026-09-03). This note covers the V4 JSONL session store in `packages/agent` and the built-in provider adapters in `packages/ai`.

## Conclusion

Pi does **not** durably keep a complete raw provider response beside a second normalized transcript copy. Its settled transcript authority is one `MessageEntry.message: AgentMessage`; an assistant message has a small semantic union (`text`, `thinking`, `toolCall`) plus provider-only fields in the same object. The JSONL backend serializes those transaction writes directly with `JSON.stringify` and appends them to the session file ([entry schema](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/session/types.ts#L16-L40), [JSONL serialization](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/session/jsonl/storage.ts#L69-L84), [append](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/session/jsonl/storage.ts#L239-L261)).

This is best described as **one canonical representation with selected provider-only extensions**, not a lossless provider envelope. There are three qualifications:

1. OpenAI reasoning is stored as both normalized `thinking` text and a serialized complete reasoning item in `thinkingSignature`; that extension can repeat summary/content bytes, but it is not a second complete response ([capture](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-responses-shared.ts#L681-L701)).
2. In-flight streams and compaction deliberately create other durable semantic copies for recovery or projection. They are not raw provider responses.
3. Unknown provider item kinds are not preserved or rejected by the OpenAI adapter; they fall through and disappear. Pi therefore does not provide lossless forward-compatible storage.

## What the canonical message retains

The shared `AssistantMessage` stores provider/API/model identity, `responseId`, provider thinking level, diagnostics, usage, normalized stop reason, raw stop reason, deferred handle, error, `endTurn`, and timestamp. Its content blocks store visible text plus optional `textSignature`; reasoning text plus optional opaque/serialized `thinkingSignature` and `redacted`; and tool-call ID/name/parsed arguments plus optional Google thought signature and OpenAI namespace. `ToolResultMessage` stores call identity, content, UI/log details, tool usage, dynamically added tool names, and error status ([message types](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/types.ts#L351-L381), [assistant and tool-result fields](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/types.ts#L428-L470)). A finalized tool result becomes one `ToolResultMessage`, then one transcript entry; no provider-shaped tool-result copy is retained ([normalization](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/execution/tools.ts#L183-L209), [entry commit](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/tool-placement.ts#L145-L180)).

Provider adapters assemble this object in memory while consuming their streams. For OpenAI Responses:

- a reasoning output item becomes a `thinking` block and the complete item JSON becomes `thinkingSignature`;
- an assistant message becomes text plus an encoded item ID/phase in `textSignature`;
- a function/custom-tool call becomes a canonical tool call with a composite call/item ID, parsed arguments, and optional namespace;
- response-level ID, usage, status, and incomplete reason are selected into assistant fields.

The relevant conversion is explicit and field-selective ([known output slots](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-responses-shared.ts#L425-L531), [terminal field selection](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-responses-shared.ts#L533-L595), [completed items](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-responses-shared.ts#L681-L740)). Anthropic follows the same shape: response ID, text, reasoning/signature or redacted encrypted data, and tool calls are selected into the shared message ([Anthropic import](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/anthropic-messages.ts#L593-L664)).

There is no durable HTTP body, SSE event envelope, SDK response, or complete provider response object in these paths. The provider request body is also an in-memory value; Codex explicitly strips parser scratch buffers before returning an error message ([in-memory output/body](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-codex-responses.ts#L230-L283), [scratch cleanup](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-codex-responses.ts#L470-L485)).

## Settlement, recovery, and retries

Before crossing the provider boundary, the harness durably records an `assistant.effect_pending` state with attempt number and reserved response/usage IDs. It then streams into an in-memory `AssistantMessage`; settlement commits that single message entry and its usage row ([intent and execution](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/generation.ts#L132-L202), [settlement](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/response.ts#L184-L206), [message write](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/response.ts#L321-L355)).

During the stream, pi also commits compact `AssistantMessageFrame` records containing canonical starts/deltas/ends and provider extension fields. On normal settlement their logical list is deleted; after a crash they are reduced into an interrupted canonical assistant message and settled without calling the provider again ([frame schema](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/utils/assistant-message-frame.ts#L4-L33), [durable frame append](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/progress.ts#L35-L87), [reduction](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/utils/assistant-message-frame.ts#L368-L490), [crash settlement](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/recovery.ts#L22-L83)). Because JSONL commits are append-only, earlier frame lines remain physically in that file after the delete tombstone even though the materialized state removes the list ([list-delete semantics](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/session/in-memory-storage-state.ts#L124-L138)).

Retryable failures are themselves committed as error assistant entries, then the durable operation moves to `assistant.retry_wait`; failed/aborted/deferred assistant entries are filtered out of future model context ([retry classification](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/response.ts#L275-L291), [context filter](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/session/context.ts#L24-L39)). A later attempt rereads transcript context and reruns live system-prompt, tool, hook, and provider-payload construction. Pi does not persist the exact prior request bytes, and this path does not promise byte-identical reconstruction ([generation rebuild](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/generation.ts#L56-L125), [retry re-entry](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/generation.ts#L284-L301)).

## Request reconstruction and response IDs

Each request is rebuilt from the selected session entries, projected agent messages, and current provider adapter. The default projection passes standard user/assistant/tool-result messages through and maps compaction/branch/custom records to provider-neutral messages ([agent projection](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/messages.ts#L124-L168)). OpenAI reconstruction parses `thinkingSignature` back into a reasoning item, rebuilds assistant output text from text plus ID/phase, rebuilds tool calls from canonical fields, and converts tool results from their content ([OpenAI export](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-responses-shared.ts#L212-L312)). Anthropic similarly replays opaque/redacted reasoning signatures from the same canonical block ([Anthropic export](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/anthropic-messages.ts#L1275-L1328)).

OpenAI and Codex requests set `store: false`; Codex also asks for `reasoning.encrypted_content`, showing why that provider-only extension is retained ([OpenAI request](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-responses.ts#L265-L299), [Codex request](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-codex-responses.ts#L519-L560)). `responseId` is durable inside `AssistantMessage`, but normal full-history reconstruction does not consume it. Codex can instead send `previous_response_id` only through a process-local WebSocket connection cache holding the previous request body and reconstructed response items; loss of that cache falls back to the full rebuilt context ([process-local cache](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-codex-responses.ts#L845-L878), [delta eligibility](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-codex-responses.ts#L1391-L1442), [cache update](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-codex-responses.ts#L1483-L1535)).

## Unknown fields and item kinds

The canonical content union has no opaque/unknown block. OpenAI's slot creator recognizes only reasoning, message, function call, and custom tool call, then returns `undefined`; the event loop has no reject-or-preserve fallback for another output item or event type ([closed slot set](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-responses-shared.ts#L425-L531), [no fallback branch](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-responses-shared.ts#L681-L757)). Codex forwards otherwise-unrecognized events to that same processor ([Codex event mapping](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/ai/src/api/openai-codex-responses.ts#L717-L753)).

Unknown fields happen to survive only when embedded in the complete JSON-stringified OpenAI reasoning item. Message and tool-call records retain only the explicitly selected fields above. Pi therefore chooses a practical adapter-defined subset, not a general lossless conversion boundary.

## Compaction

Compaction does not create a raw provider copy. It commits a derived summary plus copies of recent canonical `AgentMessage`s in `retainedTail`; the old transcript entries remain ancestors. Future context selects the newest compaction entry, turns its summary into a user message, appends the retained tail, and then appends later entries ([compaction record](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/session/types.ts#L33-L40), [compaction commit](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/structural.ts#L259-L276), [context projection](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/session/context.ts#L10-L39)).

The retained tail preserves its messages' provider extensions, while summarized messages' signatures/encrypted continuation are no longer replayed in the active request. Pi also durably stores the full compaction preparation (`messagesToSummarize`, split-turn prefix, and retained tail) while the operation is recoverable, then logically deletes operation preparations at terminal cleanup ([durable preparation](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/structural.ts#L66-L87), [cleanup](https://github.com/badlogic/pi-mono/blob/7d399e7be83cb7ffb0236b2925ba21f2bc9efe18/packages/agent/src/harness/runtime/drive/terminal.ts#L25-L59)). These are intentional semantic recovery/projection duplicates, not provider-response duplication.
