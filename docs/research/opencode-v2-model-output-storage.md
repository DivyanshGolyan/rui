# OpenCode V2 model-output storage

Checked 2026-09-03 against `anomalyco/opencode` commit [`f12e14cf1640cbf0dfb6b1ff425b2daaef459eec`](https://github.com/anomalyco/opencode/tree/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec). This note covers the repository's **current V2 Session core** (`packages/core/src/session` and `packages/llm`), not the legacy `packages/opencode/src/session/message-v2.ts` compatibility path.

## Verdict

OpenCode V2 does **not** durably retain a raw provider response alongside a normalized conversation copy. The closer description is:

> One normalized semantic transcript, with adapter-selected provider-only extensions on known reasoning and tool records.

There is one storage-level qualification: OpenCode is event sourced, so normalized semantic facts exist in both the durable `event` log and the `session_message` read projection. That is event/projection duplication, not raw-provider/normalized duplication. The event table stores typed event data, while the message table stores the projected `SessionMessage` JSON ([event schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/event/sql.ts#L4-L24), [message schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/sql.ts#L119-L138)). Both are committed in the same durable-event transaction ([commit path](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/event.ts#L236-L348)). There is no provider-response record in that path.

The wire response is framed, schema-decoded, and translated by a protocol state machine into provider-neutral `LLMEvent`s in memory ([protocol contract](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/route/protocol.ts#L26-L63), [stream execution](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/route/client.ts#L279-L294)). The Session runner consumes those events and publishes selected semantic Session events ([runner](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/llm.ts#L235-L280)); the projector encodes the resulting normalized message into `session_message.data` ([projector](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/projector.ts#L111-L129), [insert](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/projector.ts#L192-L207)).

## What survives

- **Assistant text:** the publisher accumulates deltas in an in-memory `Map<string, string[]>`, then durably publishes the completed text; the delta event itself is explicitly live-only ([assembly](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/publish-llm-event.ts#L91-L130), [event durability](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/schema/src/session-event.ts#L197-L231)). The canonical assistant schema stores `{ type: "text", id, text }`, not the provider's message object ([schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/schema/src/session-message.ts#L140-L162)).

- **Reasoning and continuation state:** reasoning text is normalized, while provider-only replay material is carried in `providerMetadata`, an open provider-keyed record ([metadata schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/schema/src/llm.ts#L3-L9), [reasoning schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/schema/src/session-message.ts#L147-L157)). OpenAI Responses places the item ID and encrypted reasoning content there ([extraction](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L642-L688), [finalization](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L846-L869)); Anthropic places its thinking signature there ([parse](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/anthropic-messages.ts#L717-L741)); Gemini does the same for `thoughtSignature` ([parse](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/gemini.ts#L417-L459)). The reverse adapters reconstruct each provider's native continuation fields from that metadata: OpenAI rebuilds reasoning items with encrypted content ([lowering](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L283-L299), [replay](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L370-L408)), Anthropic restores `signature` ([lowering](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/anthropic-messages.ts#L442-L455)), and Gemini restores `thoughtSignature` ([lowering](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/gemini.ts#L229-L247)). OpenAI routes default to `store: false`, and GPT-5 defaults request encrypted reasoning specifically so this stateless reconstruction works without `previous_response_id` ([defaults](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/providers/openai-options.ts#L44-L70), [route](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L984-L992)).

- **Tool calls and results:** the canonical tool record owns the call ID, name, semantic state, structured/content output, and optional provider fields. Call-side and result-side provider metadata are stored separately ([schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/schema/src/session-message.ts#L81-L138)). The publisher records the parsed call before execution and normalizes settlement into structured/content data ([call](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/publish-llm-event.ts#L313-L335), [result](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/publish-llm-event.ts#L337-L373)). Provider-hosted tools are the deliberate opaque-payload exception: the OpenAI adapter embeds the captured hosted-tool item as the tool's JSON `result`, still inside the one canonical tool record rather than as a second complete provider response ([adapter](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L570-L603)).

- **Model affinity:** provider metadata is replayed only when the historical assistant message used the same provider/model and did not fail. On a model switch, reasoning text becomes ordinary assistant text and the provider metadata is omitted ([reconstruction rule](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/to-llm-message.ts#L70-L105)).

## What does not survive

- **Raw response bodies and complete response objects:** none are written by the Session output path. Even OpenAI's response ID is only attached to the in-memory finish event ([adapter](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L875-L888)); the Session publisher ignores `finish` entirely and reduces `step-finish` to normalized reason/token fields ([publisher](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/publish-llm-event.ts#L396-L407)). The same reduction discards the raw provider usage payload even though the LLM-layer `Usage` object makes it available transiently ([LLM schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/schema/events.ts#L41-L59), [Session reduction](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/publish-llm-event.ts#L16-L28)).

- **Unknown output item kinds:** there is no opaque/unknown assistant-content variant; the durable union is only text, reasoning, or tool ([schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/schema/src/session-message.ts#L140-L162)). OpenAI's event parser accepts any event/item `type`, but an unrecognized event reaches the no-event default, and an unrecognized completed item likewise emits nothing ([event dispatch](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L923-L948), [item dispatch](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L808-L872)). Extra response fields may be admitted transiently by the response schema, but only explicitly mapped fields become `LLMEvent`s ([wire schema](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/protocols/openai-responses.ts#L212-L234)). Therefore OpenCode V2 is not a lossless or fail-closed precedent for future provider item kinds: unknown kinds are silently absent from durable history.

## Retries, reconstruction, and compaction

Provider requests are reconstructed from durable projected history. Before each turn the runner reloads Session history, translates it to provider-neutral LLM messages, builds a fresh request, then calls `llm.stream(request)` ([assembly](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/llm.ts#L197-L239)). The LLM route then creates a validated provider body and transport-private prepared value in memory ([compile/dispatch](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/route/client.ts#L341-L379)). It does not reload stored provider JSON.

HTTP status retries are process-local: the transport retries the same request up to two times with backoff ([policy](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/route/executor.ts#L35-L38), [loop](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/llm/src/route/executor.ts#L345-L379)). V2 does not durably identify those attempts; retry notices and post-crash continuation recovery are explicitly unfinished ([runner status](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/llm.ts#L60-L90), [V2 spec](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/specs/v2/session.md#L101-L109)).

Compaction preserves the old semantic transcript durably but changes the active model view to a new canonical `compaction` message. Its serializer deliberately retains only readable text/reasoning/tool facts, not provider metadata or native response items ([serializer](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/compaction.ts#L88-L120)); the completed checkpoint stores a summary plus bounded recent text ([checkpoint](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/compaction.ts#L176-L230)). History selection starts at the latest compaction for future requests ([selection](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/history.ts#L13-L50)), and request reconstruction renders that checkpoint as user-visible historical context ([rendering](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/packages/core/src/session/runner/to-llm-message.ts#L147-L171)). Thus provider signatures and encrypted reasoning intentionally do not cross a compaction boundary; the repository's V2 specification states that design explicitly ([spec](https://github.com/anomalyco/opencode/blob/f12e14cf1640cbf0dfb6b1ff425b2daaef459eec/specs/v2/session.md#L111-L121)).

## Relevance to OnePage

OpenCode supports a single durable semantic representation with provider-only fields rather than two complete copies. Its adapters prove that IDs, signatures, encrypted reasoning, and hosted-tool payloads can live as extensions on known canonical items and be reconstructed provider-side. But it does **not** answer the forward-compatibility problem safely: unknown provider items are ignored, response IDs and some response-level metadata are dropped, retries lack durable attempt identity, and compaction deliberately ends native replay. Those are limitations to evaluate, not behaviors to inherit automatically.
