# Pi Bash output spillover

Research date: 2026-09-07. Primary-source inspection only; no benchmark, crash test or OnePage policy acceptance. GitHub redirects `badlogic/pi-mono` to `earendil-works/pi`; current `main` resolved through `gh api` to [`9767ba275f3e9a5ee0f5c5342249b629ab1b2282`](https://github.com/earendil-works/pi/tree/9767ba275f3e9a5ee0f5c5342249b629ab1b2282).

## Finding

Pi separates a bounded model-visible preview from full captured output. Both its coding-agent and newer agent harness return the last **2,000 lines or 50 KiB**, whichever limits the preview first, and append a `Full output: <path>` reference when truncated. Those numbers limit the preview, not total capture. Both Bash schemas make command timeout optional, with no default. [Coding-agent Bash](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/bash.ts#L222-L369), [harness Bash](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/tools/bash.ts#L8-L142), [preview constants](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/utils/truncate.ts#L1-L12).

## Capture and retrieval

The coding-agent accumulator initially retains raw chunks, then lazily opens `os.tmpdir()/pi-bash-<random>.log` when raw bytes, decoded bytes or lines exceed the preview threshold. It writes the retained prefix and subsequent raw chunks to that file, while maintaining a decoded tail. Stdout and stderr feed the same accumulator; the file contains their interleaved received chunks, without stream labels. The tail truncator can retain part of the final line when that line alone exceeds the byte limit. [Accumulator](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/output-accumulator.ts#L19-L118), [spill creation](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/output-accumulator.ts#L205-L220), [pipe wiring](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/bash.ts#L120-L122), [tail truncation](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/utils/truncate.ts#L216-L294).

The reference is an ordinary filesystem path, not a content-store identifier or special retrieval capability. The coding-agent Read tool accepts absolute paths and line `offset`/`limit`, and suggests Bash for an oversized individual line. However, that Read implementation reads the entire file before splitting and slicing it: bounded returned text does not establish bounded retrieval memory. [Read schema/default filesystem operations](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/read.ts#L14-L45), [read and slice](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/read.ts#L128-L174).

## Newer harness: better write ownership

The newer Bash tool requests `capture: { limits: ..., spill: true }` from its execution environment. The Node environment retains an initial raw prefix, creates a named log in a fresh temporary directory on overflow, and appends subsequent chunks. It pauses both child output pipes while opening the spill file and when `WriteStream.write()` reports backpressure; it resumes on `drain`. The stream high-water mark is **8 MiB**, a buffering threshold rather than a total-file limit. A spill error kills the process and produces an error explaining that complete output could not be preserved. [Harness request](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/tools/bash.ts#L75-L108), [buffer threshold](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/env/nodejs.ts#L37-L42), [spill ownership and errors](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/env/nodejs.ts#L462-L522), [capture and settlement](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/env/nodejs.ts#L561-L625).

This differs materially from the coding-agent accumulator, which ignores the return value of `write()` and installs a stream error listener only while closing. Its rolling decoded tail does not bound the writable stream queue under a slow disk. Both preview implementations also allocate decoded strings and temporary encoded buffers while trimming; neither source inspection establishes an exact total resident-memory ceiling. [Older writes and close](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/output-accumulator.ts#L64-L141), [older tail allocation](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/output-accumulator.ts#L148-L194), [newer preview trimming](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/utils/output-capture.ts#L125-L145).

## Lifetime and resource limits

The inspected spill paths close streams but do not unlink the output, fsync it, register a durable content owner, or implement crash reconciliation/expiry. The newer environment's `cleanup()` kills tracked children; it does not remove temporary output directories. These are named files that can remain after invocation or process exit, but the code does not promise survival of a crash, operating-system temporary-file cleanup or later deletion. A path in a saved Tool Result is not proof that its target remains available or complete. [Older close](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/coding-agent/src/core/tools/output-accumulator.ts#L121-L141), [newer temp creation and cleanup](https://github.com/earendil-works/pi/blob/9767ba275f3e9a5ee0f5c5342249b629ab1b2282/packages/agent/src/harness/env/nodejs.ts#L821-L850).

Neither inspected capture implementation imposes a total per-command file-size ceiling or an aggregate temporary-storage quota. The newer implementation handles actual write failure; it does not reserve/check an application-wide storage allowance before growth. Pi therefore supports the product pattern **small inline preview plus separately retrievable full output**, but does not supply OnePage's aggregate-storage admission, durable reference lifetime, restart or reclamation policy. Those remain separate decisions; adopting Pi's preview need not adopt its temporary-file lifetime.
