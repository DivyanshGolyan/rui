One Rui input stream after the renderer lands

Keep vaxis as the terminal decoder. Consolidate Rui's framing, semantic normalization and input deadlines in TerminalInput, then bind recovery alongside other decoded keys.

Proposed, not implemented Implementation only after renderer landing and authorization

Needs from Divyansh: accept or redirect Q1, Q2 and Q3 before implementation. Recommendations below are design defaults, not permission to implement.

Base: published wip/sole-renderer-h at f15c2b57. Design branch design/input-stream-after-renderer. This proposal does not alter the accepted Architecture or frozen qualification.

Scope: one invocation-local stream adapter used by the full-screen frontend and one-shot terminal chooser. No libvaxis rewrite, Host change, persistent format, compatibility path or preservation of broken input behavior.

Estimate: 2–3 engineer-days after decisions and renderer landing, medium confidence, including focused implementation and evidence. Native platform qualification scheduling is additional. No implementation or native campaign runs in this design task.

One adapter owns the stream; consumers own actions

D1Extend the existing owner

TerminalInput owns the vaxis parser, undecoded bytes, consumed suffix, paste state and deadline state. It survives draft-bank switches and choice-editor replacement. One-shot readLine owns an instance for its terminal-custody interval; separate processes do not share state.

The adapter frames complete UTF-8 scalars and X10 mouse reports, preserves double-ESC suffixes and the DECRPM set/reset facts vaxis loses, and honors vaxis's consumed count. A consumed unknown sequence never becomes typed suffix text. Existing bounded vaxis safety patches remain decoder maintenance, not a new Rui parser architecture.

D2Keep the stream interface small

Evolve the existing feed, next, pending and expire interface rather than introduce another event loop. feed(byte, observed_at) advances byte custody. next() drains retained suffix units before another byte. A wait-state query returns the pending kind and absolute deadline. Expiry consumes an observed-empty fact and its monotonic time, not elapsed time alone.

Returned units distinguish key press, key release, paste boundaries, literal paste text, terminal report, ignored complete input and invalid input. They carry typed-versus-pasted provenance. Keys retain identity, modifiers and associated text; they are not editor commands. Escape expiry produces an ordinary decoded Escape through this same interface, never a direct navigation callback.

SessionTerminal owns reads, polling, terminal modes and restoration, but no duration constants or pending-input clock. The one-shot reader uses the same policy. TerminalEditor owns edits and validation. SessionFrontend selects the displayed editor, applies contextual bindings and invokes SessionSubmission; it never recognizes recovery from a raw byte.

Equivalent encodings produce equivalent editor outcomes

For a fixed initial draft, cursor, editor, consent state and submission state, supported encodings of the same semantic key produce the same edit, navigation, rejection or recovery request. Compare the draft bytes, cursor, emitted actions and exact submission identity, not only whether nearby text survives. Terminal-transformed keys with identical received bytes cannot be distinguished.

D3Normalize identity without discarding intent

Raw C0 and encoded C0 aliases use the same ground-key mapping, including BS/DEL, CR, LF and Tab. Explicit Ctrl-I aliases Tab; explicit Ctrl-J aliases Enter, consuming only the Ctrl bit that defines that alias. Preserve additional Shift, Alt and other meaningful modifiers rather than stripping them to force equivalence. Case/layout metadata from CSI-u remains available for binding comparisons; do not lowercase ordinary inserted text.

Unmodified printable CSI-u or case27 without associated text synthesizes the Unicode scalar's text, after scalar validation. If valid associated text is present, use it for ordinary insertion. Bound control and modified chords consume or reject that text with the key. Lock bits are metadata rather than command modifiers. Press and repeat apply the binding; release does not edit or recover. The current vaxis pin collapses repeat into press, so no repeat-specific recovery semantics are promised.

Q2 recommends a narrow recognizer for complete CSI 27;modifier;code~ inside the same adapter. Parse bounded decimal fields, valid scalar range and allowed modifier bits; map the result into the same key normalizer. It must precede vaxis's silent consumption of case27, not inspect a lost key afterward. Generic CSI-u, reports and other escape grammar stay with vaxis. This is support for a terminal encoding, not an old-Rui compatibility mode.

D4Preserve every ESC prefix

For ESC followed by a non-introducer key, wait for its complete scalar or ground control, decode it as if alone, then add Alt. Do not send vaxis's raw two-byte Alt fallback a partial UTF-8 scalar. o ESC . k leaves ok; ESC CR is one Alt-Enter, never an abandoned prefix plus a submission.

On a second ESC, emit the first as Escape and retain the second as a fresh prefix. Thus ESC ESC [200~ is Escape followed by paste start, and ESC ESC [A is Escape followed by Up. Two ESCs with no suffix eventually produce two Escapes, not the base's single expired Escape. Encoded Alt-Escape retains Alt identity; the frontend may bind it to the same close-view action without calling the encodings identical.

Expire input only after an actual empty read

D5Use one 80 ms / 2 s inactivity policy

Keep the existing durations as proposed defaults: 80 ms for a bare ESC and 2 s for an incomplete sequence, UTF-8 scalar or open paste. Each successfully observed byte advances the adapter's inactivity clock. Completing input clears the deadline; changing from bare ESC to recognized incomplete input selects 2 s from that byte. Retained suffix bytes keep their original observation time, not the later time when next() processes them.

First drain adapter output and retained bytes. Then attempt a nonblocking terminal read. A byte wins over an overdue timer. Only EAGAIN or a zero-ready poll followed by a nonblocking read that confirms no byte permits expiry at or beyond the deadline. EOF and I/O errors are separate outcomes. Spurious readiness, interrupted polls, redraws, editor changes and polling quanta never renew input inactivity.

The reader waits for the lesser of its caller's service budget and the adapter's remaining deadline, rounding poll time up to milliseconds and rechecking monotonic time afterward. Exhausting a service budget means “not yet serviced”, never “input empty”. No deadline applies in the ground state. Empty open paste remains pending even when no scalar bytes are buffered.

Both terminal readers need nonblocking reads to make the empty observation truthful after spurious readiness. Full-screen already owns nonblocking descriptor flags. The one-shot owner must save and restore its input flags within its existing cleanup, independently of termios restoration and output drain. Changing the read discipline must not change its pre-choice flush or return success before cleanup succeeds.

Q3 makes this readiness rule explicit. Rui cannot know whether a queued byte arrived before or after the nominal deadline while rendering was blocked. It chooses available bytes over retrospective expiry. Therefore 80 ms and 2 s are inactivity decisions at service boundaries, not total invocation deadlines or scheduler-latency guarantees. Continuous input can keep a paste open, with bounded memory; external interruption still restores the terminal.

Escape expiry only releases decoder custody and emits Escape. It does not make an Action fresh. After handling it, consent still needs the current complete prompt write, no pending stream state and an independently observed empty input boundary. A spent byte-service budget or redraw cannot grant readiness.

Recovery binds a decoded Ctrl-R to the original request

D6Keep command policy out of the adapter

The full-screen frontend handles a typed Ctrl-R press after normalization and before passing an unbound control to the editor. With no active consent it calls the existing original-bound requestRecovery. With consent active but its Action hidden, it preserves the draft, invalidates choice readiness and displays the existing return-to-Action notice. With the Action visible it follows the existing choice rejection policy, without a recovery request.

The submission owner remains authoritative for idle no-op, deferred Admission recovery, acceptance/discard retirement, retained rejection and exact Store/Session/key/content identity. Key normalization cannot resend work, select another original or transfer a gesture to a successor. Pasted Ctrl-R and key-release reports cannot request recovery. One-shot provider choice has no recovery command; Ctrl-R remains an invalid choice through ordinary editor policy.

The one-shot reader's raw BS/DEL fast path and raw-byte “may edit” classification move behind decoded editing outcomes. Repaint batching may combine equivalent deletions but cannot skip semantic handling. Keep its separate drain/flush prompt boundary and full-screen's decoder-aware readiness boundary. Sharing stream semantics does not merge those terminal-custody contracts.

Retain bounded custody until a safe end

D7No event queue or second draft copy

One adapter owns a 4,096-byte undecoded-frame buffer, its existing vaxis parser and a few timestamps per active terminal invocation. Completed paste text streams directly to the selected editor's existing storage; paste never accumulates as a whole in the adapter. The full-screen owner's two 65,536-byte draft banks and command snapshot remain separate. A choice retains its existing 64-byte capacity. No per-Session or dormant-population allocation appears.

Returned text borrows adapter bytes or vaxis scratch only until the next feed, next or expiry mutation. Apply it synchronously before advancing. Any actual asynchronous consumer must copy into its already-owned bounded destination, not retain the borrowed slice. Terminal replies use no OSC-52 payload allocation. Measure parser size and stack footprint at implementation time rather than call these bounds measured RSS savings.

D8Rejected input never becomes an accepted prefix

Complete malformed input, unsupported modifier values, invalid UTF-8 and semantic editor overflow reject the active attempt. Rejection remains sticky until its ordinary unpasted line end; then full-screen clears only active composition and one-shot returns its typed error. A sealed original and the other draft bank remain intact. Unknown complete sequences that vaxis intentionally consumes without an event are ignored, not reinterpreted as text.

Incomplete expiry, undecoded-frame overflow, or a parser error with no trustworthy consumed count is fatal for the terminal-custody interval. Restore the terminal before returning the typed failure. This deliberately avoids guessing a frame boundary after arbitrary lost bytes. EOF with a partial scalar, sequence or paste is incomplete input, never a successful line. Empty ground-state EOF keeps the consumer's existing empty-versus-nonempty-line contract.

Inside paste, retain custody through the exact end delimiter even after invalid content or draft overflow. Nested paste start and encoded keys/reports are invalid literal content, not terminal events. A replacement editor that did not observe this paste start rejects its remainder. No timeout, editor reset or newline can turn a paste tail into fresh consent.

Outside paste, raw Ctrl-C or Ctrl-D can abort a partial frame and deliver the normalized cancellation key. An ordinary CR/LF interrupting an incomplete non-Alt frame rejects that attempt rather than submitting the old draft. A Ctrl-R embedded in an unfinished frame is not a recovery gesture. Encoded keys embedded inside a malformed outer frame are not promised the same meaning as clean ground-state keys. These interruption rules belong to framing, not a raw frontend shortcut.

Test the same bytes through the adapter and real consumers

T1Share expectations, not implementation-derived answers

TD2 owns src/terminal_input_equivalence_test.zig and optional tests/integration/input_equivalence.py on td2/input-equivalence. TD4 owns tests/qualification/direct-pty/ on wip/td4-direct-pty. Coordinate by stable case names and explicit contracts. Their current-base failures remain current-base findings, not obligations to implement this proposal before landing.

TD2 reports a 44-row, four-lane Wire{bytes|unavailable(reason)} matrix with independent before/caret/after, expected cursor, editor Event and submission count, exercised at every byte split in ordinary and choice editors. Retain unavailable reasons. Kitty named navigation uses real CSI letter/tilde sequences; case27 has no navigation-keypad encoding. Legacy Shift-Enter transformed into CR is explicitly non-equivalent, not an available newline encoding. Matrix runtime results are pending at this design revision.

A future case records id, encoding, bytes_hex, chunks, observed_at, empty_observations, initial_draft, cursor, editor_kind, consent_state, submission_state, expected_units, expected_draft, expected_cursor, expected_actions. Provenance and press/release belong in expected units. Timing observations use relative monotonic time. Encodings with different semantic meaning have different expected outcomes, even when they look alike.

DirectPTY additionally records exact write chunks and send times, prompt/readiness witnesses, captured Message or Decision bytes and identity, terminal transcript bytes, interpreted cursor/screen assertions, exit outcome and restored attributes. Sender timestamps prove injection, not kernel arrival or owner-read time. A transcript alone cannot prove no capture; an unchanged final string cannot prove no transient recovery. Count captures, mutation exchanges and recovery actions independently.

TD4's current interface, separately from the future observation contract

The owner reports matrix.py BINARY --output fresh_dir --jobs 4 --vectors JSON --row NAME. Each vector contains name, scenario: editor|expiry|recovery, chunks: [{hex, delay_before}|{resize:[columns,rows]}] and exact submitted expected text. Delays are seconds. DirectPty.send writes directly to the PTY master without tmux.

It retains successful writes in input.bin, raw output.bin and stderr.bin before parsing, and monotonic launch/input/committed-observation/resize/retirement records in events.jsonl. ScreenCapture checks committed draft and caret. Its asymmetric recovery fixture checks exact original same-key/body replay and next draft cafXYé! with its non-tail cursor.

Ordinary 20 ms fragments, 150 ms ESC and current 2 s incomplete cases exercise existing behavior. These send clocks do not establish kernel arrival, delayed renderer service or readiness-before-expiry precedence. T4 requires deterministic read/empty observations at the future owner interface, followed by a focused held-service integration if a suitable production seam exists. TD4's reported interface is not yet runtime-witnessed here, and no changes to its frozen qualification are requested.

Three product choices need acceptance before implementation

Q1Make Alt-Enter a newline chord?

Recommend yes. Normalize raw ESC-CR/LF, CSI-u Alt-Enter and case27 Alt-Enter to one chord that inserts a composer newline, like Shift-Enter. The base drops Alt-Enter but inserts a newline for Alt-Ctrl-J; preserving that difference defeats equivalence. Alternative: drop all Alt-Enter variants as unbound, retaining Shift-Enter alone. Either choice must never submit a prefix. This is a proposed behavior change, not already accepted Architecture.

Q2Support modifyOtherKeys case27 now?

Recommend the narrow adapter recognizer. It gives all three encodings the same key semantics without changing generic vaxis decoding. Alternative: explicitly classify case27 as unsupported and report it visibly; then exclude it from supported equivalence claims. Silently consuming it is not support. Do not add a negotiation mode or fallback parser for old Rui clients.

Q3Prefer queued bytes over retrospective timeout?

Recommend yes. Service readable input before expiring the pending frame, with 80 ms / 2 s as inactivity defaults. This tolerates renderer scheduling delay but may join a genuinely late suffix. Alternative: elapsed-time-first expiry splits queued chords after slow processing. Precise arrival-based expiry would require a different timestamped acquisition owner and queue, beyond this consolidation. No such machinery is proposed.

The design otherwise chooses one stream owner, post-decode contextual recovery, two events for two isolated ESCs, fatal unknown-boundary framing failure and no compatibility paths. These are reviewable recommendations in this proposal. They do not silently amend canonical contracts.

Keep the consolidation bounded

  • R1ICRNL can erase physical Enter versus Ctrl-J distinctions before Rui reads input. The contract is received semantic input, not physical-key identity. A future termios change requires its own design and evidence.
  • R2The pinned decoder can discard information, including repeat identity and DECRPM status. Retain only the narrow facts current consumers require; do not grow a parallel generic parser.
  • R3PTY injection cannot establish what a physical terminal or tmux emits. TD4 records route availability and exact bytes. Lossy terminal routes remain unavailable or distinct, not normalized into a false match.
Alternatives rejected for this scope

Replacing libvaxis would reimplement terminal protocols without fixing scattered action policy. Adding a second parser wrapper or deadline helper beside TerminalInput would leave two mutable owners. A global command normalizer would confuse one-shot choices with recovery and consent. A timestamped input thread and queue could improve arrival measurement but adds concurrency, copying and shutdown custody without a current requirement.

Out of scope: displayed-view projection redesign, renderer layout, approval state-machine redesign, Store/Host changes, capability negotiation, key remapping settings, old-format readers, migrations, canonical Architecture edits and qualification-ledger changes. After renderer landing, rebase the design onto its actual landed successor and recheck changed contracts before requesting implementation authority.
