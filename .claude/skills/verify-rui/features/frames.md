# Named frames

Renders the named states in `scripts/frames.json` using a fresh `new --no-sessions --answers realistic` run, cumulative cast and a private tmux window per state, without the tap or screen library. Requires tmux and, unless `--no-png`, Node and Playwright with Chromium. It prints the output directory (default `RUN/evidence/frames/`): plain `.txt`, `.ansi`, `.html`, 2× `.png`, `frames.json` results and an ordered `index.html`. Failed states retain their screen and reason; later states still run and the command exits nonzero. Cleanup preserves evidence; `--keep` retains the run's Host, fixture, Store and private tmux server for inspection.

A scenario has `sizes` and ordered `states`. Each state names `open` (`overview` or a previously seeded cast label), optional `cast`, `steps`, `sizes`, `theme` (`night`/`day`), `env`, `expect` and one-line `note`. Cast entries have `label`, HOME-relative `workspace`, `mode`, `messages`, optional `model` (default `gpt-6.1-sol`), `effort`, `settle` (`answered`, `pending`, `stop`), and `count` with `{n}` labels. Labels map to actual Session IDs in `run.json`. Steps are `text`, `keys` (the helper's key names, including `C-o`, `C-x`, `M-i` (Alt-I) and `S-Up`), `wait`/`gone` (20 seconds unless `timeout` is set), `sleep`, `send` (`to`, `text`, optional `wait: false`), `mouse` (`{"at": "TEXT", "do": "move" | "click"}`), or `host` (`pause`/`start`). Mouse input captures the pane, finds the first visible match, and sends SGR motion (35 M) or left press/release (0 M/m) to its first cell with 1-based coordinates through `tmux send-keys -H`; an absent target fails the state. Only the first size runs steps and captures immediately afterward; other sizes resize, settle for about 0.8 seconds and capture that same state. File and state sizes accept either a list such as `["140x40", "46x30"]` or a comma string such as `"140x40,46x30"`; file, state and CLI sizes normalize to numeric dimensions before execution. `--sizes` overrides scenario and state sizes. `--only` captures selected names while still executing their predecessors through the last selection, preserving stateful side effects. Never use an unguarded Esc on an empty draft: it leaves the conversation. These are L2 tmux layout captures, not committed-frame or physical-input proof.


The list-end and exited-pane states start at the narrow size: shrinking a dead tmux pane can push its diagnostic into scrollback, and list selection follows the first viewport. An explicit `--sizes` still overrides this order. The Host-stopped chat briefly starts the same fixture-owned Host before pausing its live connection again; merely opening a read-only conversation with a paused Host does not reproduce that diagnostic. A `wait` for `The Host stopped.` names this intentionally exited surface.

Every capture checks its actual saved text against the state's expectation: by default the last `wait` marker, provided no `text`, `keys`, `mouse`, `send` or `host` step follows it, or no markers when there is no `wait`. If one of those actions follows the last wait, the state must set `expect` explicitly; validation rejects it by name before allocating a run. A later `wait` can instead establish a new default marker. `sleep` and `gone` do not invalidate the default; the actual capture still checks it. Set `"expect": "TEXT"` or `"expect": ["TEXT", "OTHER TEXT"]` to require different text, or `"expect": []` deliberately to require none. Missing text records a failed capture with `state left before capture: TEXT`, retains all artifacts, and makes the command exit nonzero even when earlier sizes passed. Text, ANSI and HTML derive from one tmux snapshot, so they cannot silently show different phases. The transient `stopping` state has only its first size; asking for further sizes with `--sizes` still checks them and may honestly fail if stopping has already finished.

The `tool-open`, `tool-open-long` and `tool-open-nocolor` states start narrow so the selected heading remains visible when widened. They use Ctrl-O and wait for the opening notice to leave before capturing; the long-output fixture prints 32 numbered lines, exercising the 20-stored-row bound: the Bash status and stdout label plus 18 printed lines, then the exact 14-line remainder. `tool-open-two` also starts at 46×30: after opening the excerpt it reaches the narrow tail, moves up twelve rows so List is the lowest visible heading, and opens List before returning to the tail. Both quiet stored-result bands stay open when it widens to 140×40, where the Session list leaves 99 columns for the chat. `NO_COLOR` preserves the indent without painting either band. Open headings keep their original mark and text columns.
For answer-markdown changes, capture `chat,chat-scrolled,chat-top,markdown,day-chat,no-color` at both default sizes. The first three retain the full retry answer and tool summary; `markdown` seeds a compact answer so code (including a blank line and a narrow wrapped continuation), aligned table, inline name and link appear together. `day-chat` and `no-color` open that same compact answer to show light-theme bands and colour-disabled indentation. Their expectations pin the formatted table row, not raw Markdown pipes. A before comparison with an older renderer uses the same fixture and states, but a scenario copy whose table-row expectation matches its literal pipes.

`markdown-wrapped` additionally waits for the four-space continuation of the compact fenced code line at 46×30, then captures the same answer at 140×40 beside the Session list. Its capture expectations apply to both widths; the narrow wait pins the wrapped line before resizing. Include it when checking code wrapping alongside `markdown` and `chat`.

For chat-info layout changes, capture `chat-info,chat-info-model` at 140×40 and 46×30 in text and PNG. Both states use a dedicated Session with a completed three-line retry answer and a retained `keep this retry draft` draft, requiring two answer lines to stay visible above the natural-height panel even with Model open. The reply comes through the fixture provider and canonical Session history, not a painted feed substitute. Both seeded states omit Context because no estimate is available; their absence markers also reject the ordinary `alt+i info` footer. A separate usage-bearing native specimen may legitimately show a known Context estimate. Inspect that opening Model takes only its added match/overflow rows from the feed and filtering restores that space, without moving the input or bottom footer. Inspect that the panel has no internal footer, the retained input and its lower divider precede the single substituted info footer on the physical last row (no blank notice slot below), Folder uses HOME-relative `~` and preserves its right edge under left ellipsis (whole trailing components when possible, longest grapheme-aligned suffix for an oversized basename), and the actions keep their blank separator even when stacked. The merged shared Model choice edits the field’s value directly, with no separate `Filter:` row. Capture `settings-model,settings-model-filter` as well as `model-picker,model-filter`; all model states reject that label, require indented matches, and use a single quiet downward overflow row. Filtered states require the typed query in the Model value row and the naturally shortened match list; the compact size column follows only shown model names.

The `first-run`, `first-run-codex` and `first-run-key` states open a separate terminal without local credentials. Its explicit `RUI_TEST_LOGIN=waiting` fixture supplies only the device code and waits for cancellation; no token or credential exchange occurs. The key state checks masking, and the terminal is closed without saving the key.
